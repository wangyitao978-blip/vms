## 当前有效的显示/性能任务约束（不要与已撤回方案混淆）

### 550/551 格式
- **只允许添加一次性取证探针，不允许改变 `sweet_decode_texel()` 的 550/551 解码行为。**
- 明确撤回过把 550/551 当作 BGR10A2Unorm 的错误方案；不得重新实施。
- 554/555 保持 XR，除非用户另行明确要求。
- 探针目标：对符合条件的 64x64、format 550 纹理，记录前 48 个原始 32-bit words，以及 top 2 bits 的 0/1/2/3 分布。
- 探针必须先验证指针和实际 buffer 范围，按真实 stride 访问，避免越界；仅取证，不改变纹理行为。

### 离屏 IOSurface / GPU 性能
- 主要目标是让离屏渲染目标走 IOSurface 映射路径，而非落入 `calloc` heap fallback / 本地软光栅慢路径。
- 需核实 `SweetTexture.ensureRenderPixels()`、`sweet_render_surface_create()`、`r.tex_mapped` 分支优先级，以及 1 MiB 限制是否会阻断 mapped 路径。
- 不得仅凭 IOSurface 创建日志宣称映射和 host flush 全链路成功。
- 设备端验收需要结合 ring/log：surface memory 分配成功、host map 成功、host flush submitted 增长、长耗时 raster pass 消失或显著减少。

### XNU 内核根因（不能只做插件侧日志）
- 曾发现 surface create 成功但 `s->memory == NULL`，导致 fill/map 路径返回 not-ready 或空映射回复。
- 需要实际检查 `xnu/patches` 中 `SweetSurface.cpp` 相关 hunk 是否存在、是否成功应用，及构建工作流是否可能忽略 reject。
- 目标修复方向：create() 在 allocSize>0 且 memory 为空时正确分配共享内存；分配失败返回真实错误；0x104 map 路径返回真实 IOReturn，不能失败仍报告 success。
- 必须核实 payload workflow 使用的是本次新构建的 XNU kernel artifact，不能误用旧 kernel。
- XNU、payload、APK 三者依赖关系须按 workflow 实际内容判断；没有 Android 代码变更时不要无故重建 APK。
